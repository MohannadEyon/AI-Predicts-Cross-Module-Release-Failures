# AI-Predicts-Cross-Module-Release-Failures

> **Proof of Concept:** An intelligent CI/CD pipeline that uses **Google Gemini AI** to analyze Merge Request diffs and dynamically execute only the relevant Selenium/Cucumber tests — saving compute time and skipping unnecessary runs.

---

## Overview

Instead of running an entire bulky test suite for every minor code change, this pipeline:

1. Extracts the **Git diff** from a GitLab Merge Request
2. Sends the diff to **Google Gemini AI** to identify impacted application modules
3. Dynamically executes **only the relevant Selenium UI tests**
4. **Gracefully skips** tests if no logical changes are detected (e.g., comment-only edits)

---

## Architecture Flow

```
Developer → GitLab MR → Webhook → Ngrok Tunnel → Jenkins (local)
                                                        ↓
                                              Fetch MR Diff (GitLab API)
                                                        ↓
                                         impact_analyzer.ts → Gemini AI
                                                        ↓
                                          Parse JSON tags (e.g. ["Login"])
                                                        ↓
                                        Maven executes targeted Selenium tests
```

## Step-by-Step Setup Guide

### Step 1 — Expose Local Jenkins to the Internet

GitLab needs to reach your local Jenkins server via a secure tunnel. Use Ngrok to create one.

Open PowerShell and run:

```powershell
.\ngrok http --domain=your-static-domain.ngrok-free.dev 8080
```

> **Keep this terminal window running** throughout the entire process.

---

### Step 2 — Configure Jenkins

#### 2.1 Install Required Plugins

Go to **Manage Jenkins → Plugins** and confirm these are installed:

- **GitLab Plugin**
- **Pipeline**

---

#### 2.2 Set Up Maven Auto-Installer

1. Go to **Manage Jenkins → Tools**
2. Under **Maven installations**, click **Add Maven**
3. Name it exactly: `M3`
4. Check **Install automatically**
5. Click **Save**

---

#### 2.3 Add Secure Credentials

Go to **Manage Jenkins → Credentials → System → Global credentials** and add the following:

| Type | ID | Value |
|---|---|---|
| Secret Text | `GEMINI_API_KEY` | Your Google Gemini API Key |
| Secret Text | `GITLAB_TOKEN` | Your GitLab Personal Access Token |

---

#### 2.4 Create the Pipeline Job

1. Click **New Item** → choose **Pipeline** → give it a name → click **OK**
2. Under **Build Triggers**, check **Build when a change is pushed to GitLab**
3. Click **Advanced** → click **Generate** to create a **Secret Token** → **copy and save it**
4. Under **Pipeline**, select **Pipeline script from SCM**
5. Set **SCM** to **Git** and enter your GitLab repository URL
6. Click **Save**

---

### Step 3 — Configure the GitLab Webhook

1. In your GitLab project, go to **Settings → Webhooks**
2. Fill in the fields as follows:

| Field | Value |
|---|---|
| **URL** | `https://your-static-domain.ngrok-free.dev/project/Your-Job-Name` |
| **Secret Token** | The token generated by Jenkins in Step 2.4 |
| **Trigger** | ✅ Merge request events *(uncheck Push events)* |

3. Click **Add webhook** to save

---

### Step 4 — Add the Jenkinsfile

Create a file named `Jenkinsfile` in the **root of your repository** with the following content.

> 📝 **Replace `YOUR_GITLAB_PROJECT_ID_HERE`** with your actual numeric GitLab Project ID. This is required to work around a known Jenkins Windows environment variable bug.

```groovy
pipeline {
    agent any

    // Auto-installs and uses the Maven tool configured in Jenkins
    tools {
        maven 'M3'
    }

    environment {
        GEMINI_API_KEY = credentials('GEMINI_API_KEY')
        GITLAB_TOKEN   = credentials('GITLAB_TOKEN')
    }

    stages {

        stage('Fetch Code Diff') {
            steps {
                bat """
                curl --header "PRIVATE-TOKEN: %GITLAB_TOKEN%" \
                  "https://gitlab.com/api/v4/projects/YOUR_GITLAB_PROJECT_ID_HERE/merge_requests/${env.gitlabMergeRequestIid}/diffs" \
                  > pr_diff.txt
                """
            }
        }

        stage('Run Gemini Analysis') {
            steps {
                bat "npm install"
                bat "npx ts-node impact_analyzer.ts > ai_result.txt"

                script {
                    env.RAW_RESULT = readFile('ai_result.txt').trim()
                    echo "Gemini Output: ${env.RAW_RESULT}"

                    // Fallback logic if AI detects no changes (prevents Selenium crash)
                    if (env.RAW_RESULT == "" || env.RAW_RESULT == "[]") {
                        echo "AI detected no module changes. Setting tags to NONE to skip tests."
                        env.TEST_TAGS = "NONE"
                    } else {
                        env.TEST_TAGS = env.RAW_RESULT.replaceAll('\\[|\\]|\\"|\\s', '')
                    }
                }
            }
        }

        stage('Execute Maven Tests') {
            steps {
                echo "Dynamically running Maven groups: ${env.TEST_TAGS}"
                bat "mvn clean test -Dgroups=${env.TEST_TAGS}"
            }
        }

    }
}
```

**Commit and push this file to your GitLab repository.**

---

### Step 5 — Test the Pipeline End-to-End

Follow these steps to trigger a full pipeline run:

1. **Create a new branch** in your local repository
2. **Make a meaningful code change** to a specific page object or test file
3. **Commit and push** the branch to GitLab
4. **Open a Merge Request** in GitLab targeting your main branch
5. **Watch Jenkins** — the webhook will automatically trigger a build

Jenkins will:
- Fetch the MR diff from GitLab
- Send it to Gemini AI for impact analysis
- Parse the returned JSON tags (e.g., `["Login", "Checkout"]`)
- Execute only the matching Selenium/Cucumber test groups via Maven

## 🔐 Security Notes

- **Never commit API keys or tokens** directly in code. Always use Jenkins Credentials.
- Ngrok tunnels expose your local machine — use a **static domain** and restrict access if possible.
- GitLab webhook Secret Tokens prevent unauthorized pipeline triggers.

## 🧠 How the AI Analysis Works

The `impact_analyzer.ts` script:

1. Reads `pr_diff.txt` (the raw MR diff fetched from GitLab)
2. Sends the diff content to the **Gemini API** with a prompt asking it to identify impacted test modules
3. Gemini returns a **JSON array** of test tag names, e.g.:
   ```json
   ["Login", "Checkout"]
   ```
4. Jenkins strips the JSON formatting and passes the tags to Maven:
   ```
   mvn clean test -Dgroups=Login,Checkout
   ```

If the diff contains no logical code changes (e.g., only whitespace or comments), Gemini returns an empty array `[]` and the pipeline **skips all tests** gracefully.

## 🛠️ Troubleshooting

| Problem | Solution |
|---|---|
| Jenkins not receiving webhook | Verify Ngrok is running and the webhook URL matches the Jenkins job path exactly |
| `GEMINI_API_KEY` not found | Ensure the credential ID matches exactly: `GEMINI_API_KEY` |
| Maven tests not found | Confirm your test tags in `pom.xml` match what Gemini returns |
| `gitlabMergeRequestIid` is null | Ensure the GitLab plugin is installed and the trigger is set to **Merge request events** |
| `impact_analyzer.ts` fails | Run `npm install` locally and verify your `ts-node` version is compatible |
| Windows variable bug with Project ID | Hard-code the numeric GitLab Project ID directly in the `Jenkinsfile` as shown in Step 4 |
